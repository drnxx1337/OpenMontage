## Findings

### MEDIUM — `websockets` is a hard import-time dependency of the *entire* tool registry

`File: tools/audio/_realtime_session.py:10` (`from websockets.sync.client import connect`, module level) → `tools/audio/realtime_audio.py:10` → `tools/tool_registry.py:127-131` (`discover()` imports every module under `tools/` with no per-module `try/except`).

Evidence: with `websockets` blocked from `sys.meta_path`, `registry.discover()` raises `ImportError` — one optional transport disables all 155 tools, not just the realtime one. `tools/audio/realtime_audio.py:25` declares it as a *soft* dependency (`dependencies = ["python:websockets"]`), which the hard import contradicts; `requirements.txt:18` now pins `websockets>=14.0`, but `setup.py:10-21` (`install_requires`) does not, so `pip install .` produces an environment where the whole registry fails. Confidence: high (reproduced).

Fix: either add `websockets` to `setup.py` `install_requires`, or make `_realtime_session` import lazily inside `connect()` and let `check_dependencies()` report the miss. Ideally also isolate per-module import failures in `discover()` so one broken provider cannot take down the registry.

### MEDIUM — typed resume ignores legacy checkpoints: `pipeline_type` exact-match has no migration path

`File: lib/checkpoint.py:618-622` — completion now requires `cp.get("pipeline_type") == pipeline_type`; `lib/checkpoint.py:507` records `pipeline_type or "unknown"`.

Evidence (probe): a completed checkpoint whose `pipeline_type` is `"unknown"` (or absent — same predicate) yields

```
completed typed (cinematic): []
completed untyped (None):    ['research']
legacy 'unknown' typed call: []
```

so `get_next_stage()` (`lib/checkpoint.py:636`) restarts a legacy project at stage 1, re-spending on research/proposal assets. This sits against the file's own back-compat statement at `lib/checkpoint.py:474-476` ("pre-existing checkpoints … still read as completed — deliberate back-compat"), which is now only true for *gate enforcement*, not for resume. `tests/lib/test_checkpoint_resume_identity.py:31-39` pins the untyped legacy case only; nothing pins `"unknown"` + typed call. Blast radius in-repo is small (`get_completed_stages`/`get_next_stage` have no non-test callers outside `lib/`), but agent-side resume scripts are exactly the caller class this API exists for. Confidence: high for the behaviour, medium for operational impact.

Fix: backfill `pipeline_type` from `projects/<id>/project.json` (which `init_project` always writes, `lib/checkpoint.py:241`) before comparing, or add a one-shot migration that stamps `"unknown"` checkpoints; do **not** treat `"unknown"` as a wildcard, that reopens the cross-pipeline reuse hole.

### MEDIUM — provider score changes meaning for un-priceable tools, silently

`File: lib/scoring.py:423-433`, with `lib/scoring.py:271-272`.

Old: `estimate_cost` raised → `estimated_cost = 0.0` → `_compute_cost_efficiency` returns `1.0` ("free"). New: `cost_efficiency = 0.0`. Both directions are wrong-ish, but the swing is real: `cost_efficiency` carries weight 0.10 (`lib/scoring.py:43`), so an un-priceable tool loses 0.10 weighted score it previously *gained*. Any ranking that leans on `cost_efficiency` reorders. The `except Exception:` at `lib/scoring.py:425` still swallows the failure with no log, so the demotion is invisible in the run trace. Confidence: high (arithmetic from code); whether the new floor is the intended policy is a product call.

Fix: log at warning/debug when the estimate fails, and consider a neutral value (e.g. `0.5`) or an explicit "unknown_pricing" marker on `ProviderScore` rather than scoring it as maximally expensive.

### LOW — `decision_log_ref` is injected into the caller's artifact dicts before validation

A rejected write therefore still mutates the caller's in-memory `proposal_packet`/`render_report` with a `decision_log_ref` pointing at a log file that was never written. In-memory only — nothing bad lands on disk. Confidence: high.

### LOW — host rules are case-sensitive and cannot express IPv6 literals

`File: backlot/server.py:308-311`; starlette `middleware/trustedhost.py:44` does `headers.get("host", "").split(":")[0]` with no lowercasing or IPv6 bracket handling.

Evidence (direct ASGI calls, `Host` header only):

```
127.0.0.1:4750 -> 200     localhost:4750 -> 200     LOCALHOST -> 400
[::1]:4750     -> 400     board.local:4750 -> 400   127.0.0.1.attacker.example -> 400
```

`LOCALHOST` is a legal Host value per RFC 4343; it 400s. `[::1]` can never match any pattern because of the `split(":")`. Practical impact is small: `backlot/__main__.py:85` binds `127.0.0.1` (IPv4-only), browsers lowercase the host, and the README now documents the restriction (`backlot/README.md:14-16`). Confidence: high.

Fix: normalise `allowed_hosts` and the incoming host with `.lower()` (upstream starlette issue, so a tiny wrapper or a comment documenting "lowercase only" suffices).

### LOW — cache write/restore failures are swallowed without a trace

`File: tools/base_tool.py:401-402` (`except Exception: pass`), `lib/asset_cache.py:401-419, 435-436` returning `False` on I/O failure. The "cache is optional and non-fatal" contract is deliberate and documented (`tools/base_tool.py:351-353`), so this is not a correctness defect — but a silently failing cache looks identical to a cache miss, which hides disk-full/permission regressions. Confidence: high.

Fix: `logger.debug`/`warning` on the ingest path; keep the fall-through.

### LOW — `asset_cache` builds blob paths from manifest-supplied `file_name` without containment check

`File: lib/asset_cache.py:339` and `lib/asset_cache.py:426` do `self.cache_dir / entry.file_name` / `self.cache_dir / f"{key}{ext}"`. Safe today only because every in-repo caller passes a SHA-256 hex key (`tools/base_tool.py:602`) and the manifest is written by the same process. A hand-edited or shared cache directory with `"file_name": "../../x"` reads/writes outside the cache root. Confidence: high on the code shape, low on exploitability.

Fix: assert `Path(name).name == name` (and `key` is hex) before touching the filesystem.
